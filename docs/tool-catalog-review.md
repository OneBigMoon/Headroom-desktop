## 新增候选

优先评估独立浏览器验收能力，例如 microsoft/playwright-mcp（核对时未归档、未停用，9 月有推送）。价值在于不采用完整 gstack 工作流时仍能验证网页交互。若宿主已经提供浏览器控制或用户选择 gstack，应优先复用，避免重复浏览器进程和依赖。

本轮不直接接入。新增前必须验证 Node/浏览器安装、隔离用户浏览器资料、Codex/Claude 注册、超时与退出、启停/卸载恢复，以及真实网页验收；应作为独立功能更新，不混入本次检测修复。

暂不新增另一套通用记忆、提示词压缩或持续执行工具：现有目录已经覆盖这些职责，尚无明确缺口足以抵消维护成本。

## 后续值得完善的产品细节

- 分别展示安装、启用、宿主加载、最近成功运行状态，避免 Healthy 被理解为所有业务调用均成功。
- 基准节省比例应一直保留“基准数据”标识，不呈现为当前用户实际收益。
- 插件完整设置或 Hook 信任仍需宿主完成时，应提供准确步骤，不只显示已启用。
- 上游明确归档/迁移或安装契约失效时，再做有迁移提示的下架；不根据短期未提交或个人偏好自动卸载。
